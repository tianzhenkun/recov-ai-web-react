# AI Call 自定义音色风险分级执行策略

## 1. 目标

在不降低 TDD、独立审查、全量回归和真实外部验收标准的前提下，减少每个小任务重复
创建实现者、规格审查者和质量审查者造成的等待时间。

## 2. 当前基线

- 后端任务 1～4 已完成实现、规格审查、质量审查和主代理回归。
- 后端任务 5 已完成事务边界修复提交，待最终质量复审。
- 前端正式实现和真实 Qwen／浏览器／SIP 验收尚未开始。
- 工作区已有其他未提交改动，所有里程碑继续执行精确文件或 hunk 暂存，不覆盖、
  格式化或提交无关改动。

## 3. 风险分级

### 3.1 高风险任务

满足任一条件即为高风险：

- 数据库状态机、租约、幂等、并发或事务结果未知；
- 调用 Qwen、MinIO、Realtime、SIP 等外部服务并产生副作用；
- 删除、权限、跨租户隔离；
- 正式外呼任务解析、配置快照或运行生命周期；
- 真实环境验收。

高风险任务继续执行：

1. 单任务 TDD；
2. 独立规格审查；
3. 独立代码质量审查；
4. 审查问题修复后由原审查者复审；
5. 主代理运行新鲜回归。

### 3.2 中低风险任务

纯 DTO、API 客户端、菜单路由、状态文案、页面基础布局、配置映射等无独立外部副作用
的任务，可以按里程碑批量实现。

每个任务仍先写失败测试，但同一里程碑只在全部实现完成后进行一次合并规格审查和一次
合并质量审查。

## 4. 剩余里程碑

### M1：完成受理事务

- 完成后端任务 5 最终质量复审和主代理回归。
- 风险级别：高。

### M2：创建 Worker 与清理状态机

- 后端任务 6。
- 覆盖 claim、租约、退避、结果未知对账、样本及孤儿清理。
- 风险级别：高，单任务双审。

### M3：后端管理 API

- 后端任务 7～9：鉴权 API、隔离试听、删除引用检查与异步删除。
- 任务 7 的 DTO／Controller 可批量实现。
- 任务 8、9 涉及外部资源和删除，分别保留高风险审查证据。
- 里程碑结束追加一次合并回归。

### M4：正式外呼集成

- 后端任务 10～12：正式外呼音色解析与快照、Worker 生命周期和配置、后端总回归。
- 风险级别：高，正式外呼解析与启动生命周期必须独立审查。

### M5：前端基础闭环

- 前端任务 1～5：领域类型、API 客户端、菜单路由、创建弹窗、统一列表与轮询。
- 按一个里程碑批量 TDD，统一规格和质量审查。

### M6：前端外部操作闭环

- 前端任务 6～9：真实试听、删除确认、正式任务接入、前端总回归。
- 试听、删除和正式任务选择分别保留失败路径测试；里程碑统一双审。

### M7：真实联调验收

- 验收任务 1～6。
- Qwen 创建、浏览器 Realtime、删除门禁、失败清理和 SIP 分别留存真实证据。
- 不用 health、代码存在或 mock 测试代替真实外部能力验收。

## 5. 固定质量门禁

任何执行方式下均不得取消：

- 新行为先有失败测试；
- `ruff --no-fix`、格式检查和 `git diff --check`；
- 干净提交快照测试，避免项目自动修复掩盖提交问题；
- 租户隔离、幂等、删除和外部副作用的独立审查；
- 里程碑结束后的相关全量回归；
- 无关脏改动保护；
- 真实 Qwen、浏览器试听和 SIP 验收独立报告。

## 6. 进度统计

后续同时报告两类进度：

- 任务进度：已完成任务数／27；
- 里程碑进度：已完成里程碑数／7。

任务数用于保持原计划可追溯，里程碑数用于反映批量执行后的实际交付速度。

## 7. 成功标准

- 审查往返次数相较逐任务三重门禁减少至少一半；
- 高风险任务没有降低审查等级；
- 所有新增代码均有失败测试和新鲜回归证据；
- 每个里程碑只包含授权范围内的文件和 hunk；
- M7 完成前不宣称自定义音色功能已生产可用。
