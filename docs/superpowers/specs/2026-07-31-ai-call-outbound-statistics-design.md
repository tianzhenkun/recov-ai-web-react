# AI Call 外呼统计界面设计

## 1. 文档状态

- 设计日期：2026-07-31
- 设计状态：页面范围、指标口径和交互方案已确认
- 实施状态：未开始
- 适用范围：通用 AI Call 正式 SIP 外呼的历史统计页面

## 2. 目标

为 AI Call 增加一个紧凑的历史统计页面，让运营人员在一个首屏内回答以下问题：

1. 所选时间范围内共发起多少次正式拨打。
2. 其中有多少次接通，接通率是多少。
3. 当前有多少条来源于这些通话的待跟进任务。
4. 拨打量和接通率随时间如何变化。
5. 各类通话结果分别占多少。

页面优先保证统计口径准确、正式数据与测试数据隔离、异常结果可下钻，不承担实时监控或业务转化分析。

## 3. 非目标

- 不展示执行中任务、实时并发、线路健康或当前坐席状态。
- 不展示 Mock、浏览器测试或 Linphone 本地验证统计。
- 不提供任务排行、任务类型对比或执行方式筛选。
- 不展示 ASR、LLM、TTS 时延、打断成功率等 AI 质量指标。
- 不预设销售、营销、催收等业务转化率。
- 不展示客户意向分布、动态业务字段或完整语义分析标签。
- 不提供导出、自定义看板、组件拖拽或指标配置。
- 不在前端加载全部通话记录后自行聚合。
- 不把“任务已创建”“SIP 已建立”或 Mock 成功计入正式接通量。

实时执行监控、线路监控和 AI 质量分析后续如有明确需求，应使用独立页面，不继续堆叠在本统计页。

## 4. 方案选择

讨论过以下三种布局：

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| 均衡总览 | 指标卡、趋势和结果分布同屏 | 采用 |
| 趋势优先 | 放大趋势图，弱化结果分布 | 不采用，日常运营定位结果不够直接 |
| 任务优先 | 增加任务表现表格 | 不采用，当前没有跨大量任务比较的首要需求 |

最终页面只有三层：

1. 统计时间筛选。
2. 四张核心指标卡。
3. 外呼趋势和通话结果分布。

## 5. 统计范围与口径

### 5.1 数据范围

页面只统计满足以下条件的通话记录：

- `entryType = sip_outbound`；
- `startedAt` 落在用户选择的时间范围内；
- 当前登录用户拥有访问权限；
- 数据经过框架租户隔离。

`web`、`outbound_mock`、`sip_inbound`、Linphone 本地验证和其他非正式外呼来源不进入统计。

时间范围按当前租户配置时区解释。后端使用左闭右开区间：

```text
[startedAtBegin, startedAtEnd)
```

例如选择 2026-07-25 至 2026-07-31，实际查询范围为当地时区的：

```text
2026-07-25 00:00:00 <= startedAt < 2026-08-01 00:00:00
```

日期选择器禁用未来日期，V1 单次查询最多覆盖 90 个自然日。选择范围包含今天时，后端以 `generatedAt` 作为当前周期的有效结束时间，不把当天尚未发生的未来时段计入当前周期或上期对比。

### 5.2 拨打次数

`dialAttempts` 表示所选范围内正式 SIP 外呼记录的数量，包含同一外呼对象的重试。

同一 `targetId` 首次无人接听、第二次接通时：

- 拨打次数为 2；
- 接通量为 1；
- 通话结果分布包含 1 次无人接听和 1 次已接通。

页面使用“拨打次数”，不使用含义模糊的“外呼量”。

### 5.3 接通量

`connectedCalls` 表示 `callResult = connected` 的正式拨打记录数量。

接通量是拨打次数口径，不是去重客户数或去重外呼对象数。只有正式通话记录进入 `connected` 终态后才能计入；任务创建、SIP 邀请成功、振铃、Mock 成功或仅存在房间标识都不能计入。

### 5.4 接通率

```text
connectRate = connectedCalls / dialAttempts * 100%
```

- `dialAttempts = 0` 时显示 `0%`，不显示 `NaN` 或无穷大。
- 页面保留一位小数。
- 接通率变化使用“百分点”表达，例如“较上期下降 1.4 个百分点”，不写成“下降 1.4%”。

### 5.5 待跟进

`pendingFollowUps` 表示来源通话位于所选时间范围内，且真实跟进任务满足以下条件的数量：

- 存在非空 `followUpId`；
- `followUpStatus = pending`。

`followUpSuggested = true` 但尚未创建真实任务的记录不计入“待跟进”；`processing`、`completed` 和 `closed` 也不计入。

该卡片展示当前状态快照，不做上期对比。点击后进入跟进任务页面，并携带所选通话时间范围和 `followUpStatus=pending`。

### 5.6 上期对比

拨打次数、接通量和接通率显示上期对比。上期取与当前有效范围等长、紧邻当前范围之前的时间区间。

例如当前范围为 7 天：

```text
当前：[2026-07-25 00:00, 2026-08-01 00:00)
上期：[2026-07-18 00:00, 2026-07-25 00:00)
```

- 拨打次数和接通量显示相对变化率。
- 接通率显示百分点变化。
- 上期分母为 0 时显示 `-`，不伪造增长百分比。
- 待跟进只提供跳转提示，不展示变化值。
- 当前范围包含今天时，当前有效结束时间为 `generatedAt`，上期使用相同的实际时长，避免用未结束的今天与完整历史周期比较。

### 5.7 通话结果分布

稳定结果至少包含：

| 值 | 文案 |
| --- | --- |
| `connected` | 已接通 |
| `no_answer` | 无人接听 |
| `busy` | 占线 |
| `invalid_number` | 号码无效 |
| `call_failed` | 呼叫失败 |

分布基于拨打次数口径，数量之和应与 `dialAttempts` 一致。

- 尚未进入终态的记录归入“处理中”。
- 未知终态结果归入“其他”，并保留原始值供后端排查。
- 数量为 0 的“处理中”和“其他”不渲染图例。
- 前端不得把未知结果擅自映射成“呼叫失败”。

## 6. 页面结构与交互

### 6.1 页面标题

标题区只显示“外呼统计”。右侧显示最近一次成功返回的 `generatedAt`，格式为“数据更新于 HH:mm”。

不在标题区重复展示统计数字或说明性标签。

### 6.2 统计时间

统计时间使用 `DatePicker.RangePicker`，不是普通下拉框。

- 默认范围：近 7 天，包含今天。
- 快捷范围：今天、昨天、近 7 天、近 30 天。
- 用户可以选择自定义开始日期和结束日期。
- 未来日期不可选择，单次查询最多覆盖 90 个自然日。
- 不选择具体时分秒。
- 点击“查询”后统一刷新全部指标和图表。
- 点击“重置”恢复近 7 天并立即重新查询。
- 右侧提供独立刷新按钮，保留当前筛选条件。

选择今天时趋势粒度为小时；跨天范围时趋势粒度为天。日期选择变化但未点击“查询”时，不请求数据。

### 6.3 指标卡

桌面端一行显示四张卡片：

1. 拨打次数。
2. 接通量。
3. 接通率。
4. 待跟进。

拨打次数的悬浮说明为“包含同一外呼对象的重试拨打”。接通率的悬浮说明为“接通量 ÷ 拨打次数”。

前三张卡片显示上期对比；待跟进显示“点击查看跟进任务”。

点击行为：

| 卡片 | 行为 |
| --- | --- |
| 拨打次数 | 进入通话记录，预筛选所选时间和 `entryType=sip_outbound` |
| 接通量 | 在上述条件上增加 `callResult=connected` |
| 接通率 | 与接通量相同，进入已接通记录 |
| 待跟进 | 进入跟进任务页面，预筛选所选时间和 `followUpStatus=pending` |

### 6.4 外呼趋势

趋势图占内容区较宽一列，同时展示：

- 拨打次数：左轴，整数；
- 接通率：右轴，百分比；
- 今天：按小时分桶；
- 跨天：按自然日分桶。

悬浮提示必须同时展示当前桶的拨打次数、接通量和接通率，避免只看百分比无法判断样本量。

趋势点点击后进入通话记录，并携带该时间桶和对应正式外呼来源筛选。

### 6.5 通话结果分布

结果分布使用环形图，占内容区较窄一列：

- 环心显示拨打次数；
- 图例显示结果文案、数量和占比；
- 图例按固定业务顺序排列，不按数量随机重排；
- 点击扇区或图例进入通话记录，并携带时间范围、正式外呼来源和对应 `callResult`。

当没有数据时显示统一空状态，不渲染全灰环形图。

### 6.6 响应式布局

- 宽屏：四张指标卡一行，趋势图与结果分布左右排列。
- 中等宽度：指标卡保持两行两列，图表仍可左右排列。
- 窄屏：指标卡两列，两个图表上下排列。
- 图表保持稳定高度，不为填满容器而拉伸。

## 7. 数据接口

### 7.1 接口

新增只读聚合接口：

```http
GET /ai-call/outbound-statistics
```

查询参数：

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `startedAtBegin` | string | 当前时区下的开始时间 |
| `startedAtEnd` | string | 当前时区下的结束时间，接口按排他上界处理 |
| `timeZone` | string | IANA 时区，例如 `Asia/Shanghai` |
| `granularity` | `hour` 或 `day` | 趋势聚合粒度 |

返回示例：

```json
{

  "msg": "操作成功",
  "data": {
    "generatedAt": "2026-07-31T10:32:00+08:00",

      "previousStartedAt": "2026-07-18T13:28:00+08:00",
      "previousEndedAt": "2026-07-25T00:00:00+08:00"
```

### 7.2 数据规则

- 所有聚合在数据库侧完成，不把完整记录列表加载进应用内存或浏览器。
- 后端一次返回页面所需的概览、上期对比、趋势和结果分布，前端不并发拼接多份可能处于不同快照的数据。
- 后端统一应用租户隔离和权限校验。
- 计数返回 JSON number；业务 ID 如出现在下钻接口中仍必须以字符串返回。
- 后端必须验证时区、90 天范围上限以及 `granularity` 与时间范围是否匹配，不能信任前端。
- `generatedAt` 表示本次统计快照生成时间，不代表底层异步语义分析或跟进任务已全部完成。

## 8. 数据流

```text
选择日期范围
  -> 点击查询
  -> 前端计算查询起止时间和建议粒度
  -> 后端校验时区、90 天范围上限、权限和租户
  -> 数据库聚合当前周期与上一周期
  -> 一次返回概览、对比、趋势、结果分布
  -> 前端原子替换整页统计快照
```

指标或图表下钻：

```text
点击卡片、趋势点或结果扇区
  -> 构造通话记录或跟进任务 URL
  -> 保留时间范围和对应结果条件
  -> 目标页面执行后端分页查询
```

## 9. 加载、空状态与异常处理

- 首次加载显示与最终布局一致的骨架屏，避免图表区域跳动。
- 查询或刷新期间保留筛选条件，并对内容区显示加载态。
- 请求成功后原子替换整页数据，不能让指标卡和图表来自不同请求。
- 没有正式外呼数据时，四张卡片显示 0，图表显示统一空状态。
- 请求失败时不把旧快照伪装成新结果；保留筛选条件，显示“统计数据加载失败”和“重新加载”。
- 4xx 错误直接展示统一权限或参数提示，不自动重试。
- 读取请求不在页面内无限自动重试；用户可以手动重新加载。若项目统一请求层已有有界网络重试，沿用统一策略。
- 页面不轮询。实时状态变化由独立监控页面负责，当前页只在查询、重置或手动刷新时重新读取。
- 下钻目标无权限时保留当前页面，并显示统一权限提示，不泄露客户数据。

## 10. 权限与路由

- 页面路由为 `/ai-call/statistics`。
- 页面使用现有 AI Call 管理权限 `ai_call:agent:manage`，避免首版额外引入一套权限和菜单迁移。
- 统计接口必须在后端重复校验权限和租户，不能只依赖前端路由隐藏。
- 页面加入 AI Call 目录时保留现有“外呼任务”“通话记录”“跟进任务”等职责，不修改这些页面的业务边界。

## 11. 验证

### 11.1 前端自动化

- 默认日期范围为近 7 天。
- 今天、昨天、近 7 天、近 30 天和自定义范围参数正确。
- 未来日期不可选择，超过 90 天的范围不能提交。
- 选择今天请求 `granularity=hour`，跨天请求 `granularity=day`。
- 日期改变但未点击查询时不发请求。
- 查询、重置和刷新行为正确。
- 四张卡片、上期对比和百分点文案映射正确。
- 上期分母为 0 时显示 `-`。
- 拨打次数或接通量为 0 时不出现 `NaN`。
- 结果分布包含号码无效，未知结果显示为“其他”。
- 没有数据时显示空状态。
- 请求失败时显示重新加载，不展示伪最新的旧快照。
- 点击卡片、趋势点和结果扇区携带正确的时间及结果参数。
- 桌面、中等宽度和窄屏布局符合设计。

### 11.2 后端自动化

- 只统计 `entryType=sip_outbound`，排除 Mock、浏览器测试和呼入。
- 同一外呼对象重试两次时拨打次数为 2。
- 接通量只统计 `callResult=connected`。
- 接通率和百分点变化计算正确，零分母安全。
- 待跟进只统计存在真实 `followUpId` 且状态为 `pending` 的记录。
- 当前周期与上一周期边界不重叠且长度一致。
- 包含今天时使用 `generatedAt` 截断当前周期，上期使用相同实际时长。
- 超过 90 天、非法时区或不匹配粒度的请求被拒绝。
- 时区和夏令时边界聚合正确。
- 小时和自然日分桶正确。
- 结果分布总数与拨打次数一致，处理中和未知结果不会丢失。
- 聚合查询遵守租户隔离和权限。
- 聚合在数据库侧执行，不加载全部通话记录。

### 11.3 人工验收

至少准备以下正式数据：

1. 首次未接、第二次接通的同一外呼对象。
2. 已接通、无人接听、占线、号码无效和呼叫失败记录。
3. 已创建且状态为待跟进的真实跟进任务。
4. 仅有跟进建议但没有真实任务的记录。
5. Mock、浏览器测试和 SIP 呼入记录。
6. 没有任何正式外呼的日期范围。

逐项核对指标、上期对比、趋势、结果分布和下钻后的分页记录。页面展示只能证明数据库中的历史统计快照，不能替代真实 SIP、双向媒体、录音和通话终态验收。

## 12. 实施边界

本设计需要前后端协同：

- 后端新增正式外呼统计聚合接口。
- 前端新增统计页面、服务层、状态映射和自动化测试。
- 路由和菜单增加“外呼统计”入口。
- 通话记录与跟进任务页面复用现有 URL 预筛选能力；缺少的时间范围参数支持在实施计划中作为直接依赖补齐。

实施时只修改统计页及其直接依赖，不清理、不格式化、不提交当前 worktree 中其他已有脏改动。视觉伴侣生成的 `.superpowers/` 目录仅用于本地设计讨论，不进入版本控制。
