# 通用外呼统一流程与 Linphone 阶段设计

## 1. 目标

AI Call 前台只呈现一套正式外呼流程。当前阶段使用 Linphone 软电话作为被叫终端，并复用现有 SIP 会话能力完成拨号；后续接入真实 SIP 线路时，只替换或扩展拨号适配器与线路配置，不改变任务创建、调度、重试、通话记录、转人工和坐席接听流程。

成功标准：

- 前台不再出现“测试拨打”、测试场景选择或测试状态。
- “确认启动”对立即执行任务的含义是：创建任务并提交正式执行队列。
- 定时任务在计划时间到达后由同一执行器自动执行。
- Linphone 通话更新正式任务、外呼对象、拨打尝试和通话记录。
- AI 转人工仍通过正式 handoff 状态机完成，坐席媒体就绪后停止客户侧等待音。
- 后续切换真实 SIP 线路不修改前端任务流程和业务状态。

## 2. 用户流程

### 2.1 新建任务

1. 用户填写任务名称、外呼对象、提示词、音色、呼叫规则和执行计划。
2. 用户点击“校验任务”。
3. 页面展示紧凑的校验结果。
4. 校验通过后展示人工确认摘要。
5. 用户点击“确认启动”。
6. 后端以幂等方式创建任务：
   - 立即执行：进入 `SCHEDULED`，执行时间为当前时间，随后由正式任务执行器领取。
   - 定时执行：进入 `SCHEDULED`，到达 `scheduled_at` 后由同一执行器领取。
7. 前端进入任务详情页并轮询任务与对象进度。

“确认启动”不直接在浏览器中发起媒体连接，也不调用任何测试接口。浏览器只提交业务命令，执行状态以后端任务和拨打尝试为准。

### 2.2 任务执行

正式执行器按照现有呼叫规则、运营时间、并发限制和重试规则处理任务：

```text
SCHEDULED
  -> RUNNING
  -> PAUSING -> PAUSED -> RUNNING
  -> STOPPING -> STOPPED
  -> COMPLETED
  -> FAILED
```

单个外呼对象按照以下状态流转：

```text
PENDING
  -> DIALING
  -> IN_CALL
  -> COMPLETED

DIALING / IN_CALL
  -> RETRY_WAIT
  -> DIALING

PENDING / RETRY_WAIT
  -> CANCELLED
```

接口返回“已受理”只表示命令已经进入系统，不表示电话已接通。任务详情必须继续查询最终状态。

## 3. Linphone 阶段的拨号边界

### 3.1 Linphone 的角色

Linphone 不是一条独立的测试业务流程，而是当前阶段的 SIP 被叫终端。任务执行器仍然调用正式 `OutboundDialer` 接口：

```text
OutboundTaskWorker
  -> OutboundTaskExecutor
  -> SipOutboundDialer
  -> AiCallService.create_sip_session
  -> LiveKit / FreeSWITCH
  -> Linphone
```

现有 `LinphoneTestDialer` 的核心拨号逻辑复用 `create_sip_session`，可以收口为正式的 `SipOutboundDialer`。拨号器负责：

- 使用任务固化的号码、提示词场景、音色和客户名称创建 SIP 会话。
- 使用正式任务 ID、对象 ID 和尝试次数关联通话。
- 在媒体接通后把尝试更新为 `IN_CALL`。
- 等待通话记录进入终态，并映射为 `connected`、`no_answer`、`busy` 或 `call_failed`。

后续接入真实 SIP 线路时，`SipOutboundDialer` 的调用者和状态流保持不变，只调整 SIP trunk、号码路由、鉴权和线路并发配置。

### 3.2 本地阶段安全限制

- 正式执行器仍通过显式配置开关启用。
- 当前阶段只允许配置中的 Linphone 测试号码，禁止拨打未授权号码。
- 启用执行器前必须处理历史非终态 Demo 任务：先备份数据库，再由用户确认是取消历史任务还是使用隔离数据库。
- 不在代码修改或自动化验证期间自动创建真实拨打任务。

## 4. 前端改造

### 4.1 新建任务页

- “校验任务”放在表单底部右侧的普通操作区，取消 `sticky` 定位。
- 校验成功使用紧凑成功提示，包含成功图标、“校验通过”和“有效外呼对象 N 个”，不再使用高空白卡片。
- 人工确认摘要底部保留“确认启动”，操作区增加稳定的上下间距。
- 点击“确认启动”后防重复提交；成功后进入任务详情页。

### 4.2 任务详情页

- 删除“测试拨打”按钮、测试场景弹窗和“测试拨打中”状态条。
- 仅展示正式任务状态、进度、统计、配置、外呼对象和通话记录入口。
- `SCHEDULED`、`RUNNING`、`RETRY_WAIT` 等状态由轮询后端数据更新，不使用浏览器本地状态模拟。

### 4.3 前端服务

- 正式页面不再调用 `test-capability`、`test-run` 和 `test-status`。
- 后端测试接口可以暂时保留用于内部诊断，但不进入用户可见流程，也不得更新正常前台交互。

## 5. 坐席接管修复

当前后端认领响应为：

```json
{
  "handoff": {},
  "seat_token": {
    "livekit_url": "",
    "participant_token": "",
    "participant_identity": ""
  }
}
```

前端必须把 `seat_token` 与 `handoff` 解包为统一媒体凭证，再执行：

1. 使用 `livekit_url` 和 `participant_token` 连接房间。
2. 发布坐席麦克风。
3. 调用 `media-ready`，提交 `participant_identity`。
4. 后端确认 LiveKit Participant 和麦克风就绪。
5. handoff 从 `accepted` 进入 `connected`。
6. 后端停止客户侧等待音并开始人工坐席录音。

仅收到 claim 200 不算接通。连接失败或 15 秒内未媒体就绪时，必须进入现有认领超时/重新入池机制。

## 6. 异常与重试

- 创建任务重复提交：依赖 `Idempotency-Key` 返回同一任务。
- SIP 会话创建失败：记录 `call_failed` 和 `error_message`，按呼叫规则判断是否进入 `RETRY_WAIT`。
- 被叫忙：记录 `busy`，按规则重试。
- 无人接听：记录 `no_answer`，按规则重试。
- 客户挂机：收敛当前尝试和 handoff，停止等待音与录音。
- 坐席认领后媒体未连接：不得展示“已接通”，由 `claim_expires_at` 释放或结束。
- 任务停止：不再领取新对象，当前通话按既有安全结束策略收敛。

## 7. 数据与兼容边界

- 任务、对象、尝试和通话记录继续使用现有表结构。
- bigint ID 返回前端时继续使用字符串。
- 本阶段不新增“测试任务”“测试对象”或“测试通话”业务状态。
- 已产生的 `linphone_test` 历史尝试只作为本地历史数据保留，不为它们增加前台兼容逻辑。
- 不为了当前 Linphone 环境修改通用任务字段语义。

## 8. 验证

自动化验证：

- 前端测试确认任务详情不存在“测试拨打”。
- 前端测试确认校验按钮不再使用 sticky，成功结果为紧凑提示，确认区具有底部间距。
- 后端测试确认立即任务可被正式执行器领取。
- 后端测试确认正式执行器使用 SIP 拨号器并正确写入任务、对象、尝试和通话结果。
- 坐席前端测试确认认领响应正确解包 `seat_token`。
- 坐席前端测试确认 `media-ready` 携带 `participant_identity`。
- 现有任务状态、重试、暂停、停止、通话记录和 handoff 测试保持通过。

人工验证：

- 使用新建任务页创建一个只包含授权 Linphone 号码的立即执行任务。
- 不点击任何额外测试按钮，Linphone 自动收到呼叫。
- AI 通话阶段、转人工等待、坐席认领、媒体接通、等待音停止和通话结束均在同一任务中完成。
- 任务详情最终统计、对象状态和通话记录一致。

人工验证必须由用户明确开始；自动化测试和代码验证不得自行拨打 Linphone 或真实号码。

## 9. 非目标

- 本阶段不接入真实运营商 SIP trunk。
- 不新增技能组、预测式外呼或号码池。
- 不改变提示词配置和音色配置模型。
- 不为历史 Demo 测试接口继续扩展前台功能。
- 不把接口受理、任务进入 `RUNNING` 或坐席 claim 成功当作真实媒体接通。
