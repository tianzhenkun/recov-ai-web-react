# 通用 AI 外呼任务 V1 设计

## 1. 文档状态

- 设计日期：2026-07-27
- 最近修订：2026-07-28
- 设计状态：已完成产品讨论，批量名单直接上传契约已确认
- 实施状态：前端 service、Mock、页面和测试已按直接上传契约修订，真实后端尚未实现和联调
- 适用范围：`recov-ai-web-react` 的 AI Call 目录及其后续通用外呼后端

## 2. 目标

为 AI Call 增加一套与具体业务无关的通用外呼任务能力，解决以下问题：

1. 运营人员可以发起单号码或批量名单外呼。
2. 任务创建前能够发现并定位名单问题。
3. 任务执行后能够查看每个外呼对象的处理进度。
4. 每次真实拨打统一进入“通话记录”中心。
5. 任务能够安全暂停、恢复、停止和取消。

V1 优先保证状态准确、执行可控、异常可定位，不追求完整营销、催收或呼叫中心分析能力。

## 3. 范围

### 3.1 V1 包含

- 外呼任务列表。
- 单页创建任务。
- 单号码外呼。
- 批量名单上传、校验和问题明细下载。
- 立即执行和定时执行。
- 提示词、音色和呼叫规则选择。
- 任务暂停、恢复、停止和取消。
- 任务详情及外呼对象分页列表。
- 从任务或外呼对象跳转到统一通话记录。
- 通话记录按任务、外呼对象和来源筛选所需的数据关联。

### 3.2 V1 不包含

- 物业催收业务接入。
- 催收金额、回款率、账龄等业务指标。
- 通用数据看板。
- 独立质检中心。
- 独立转人工管理页面。
- 在线修改问题名单。
- 跳过错误行后继续创建。
- 草稿。
- 多步骤“上一步 / 下一步”向导。
- 任务级自定义提示词、呼叫时间或重试规则。
- 新增 OSS 管理页面、多 OSS 配置选择和自动过期清理任务。

### 3.3 第二阶段

第二阶段可以增加“通用外呼运营看板”，展示外呼次数、接通次数、接通率、平均通话时长、执行中任务、失败次数、呼叫趋势、结果分布、失败原因和任务运行情况。

看板不预设“业务成功率”。只有未来各业务接入方提供明确、可比较的业务结果定义后，才增加业务专属指标。

## 4. 信息架构

AI Call 首期相关菜单职责如下：

| 菜单 | 职责 |
| --- | --- |
| 外呼任务 | 创建、查询和控制正式外呼任务 |
| 通话记录 | 查询每一次真实拨打及其录音、转写和 AI 结果 |
| 提示词设置 | 编辑并保存提示词配置 |
| 呼叫规则 | 配置可呼叫时间、重试次数和重试间隔 |
| 通话测试台 | 管理员或研发测试浏览器通话，不作为正式外呼任务入口 |

“外呼任务”内部包含任务列表、创建页面和详情页面，不再把通话记录复制成任务详情 Tab。

## 5. 核心概念

### 5.1 标识关系

| 标识 | 含义 | 是否可空 |
| --- | --- | --- |
| `taskId` | 一次正式外呼任务 | 浏览器测试通话可空 |
| `targetId` | 任务中的一个外呼对象 | 浏览器测试通话可空 |
| `callId` | 一次真实拨打或通话 | 不可空 |
| `businessId` | 未来外部业务系统的业务标识 | 可空 |

所有 `bigint` 或业务 ID 返回前端时统一使用字符串。

正式单号码外呼同样创建一个 `taskId` 和一个 `targetId`，不能绕过任务模型直接拨打。浏览器通话测试台不创建 `taskId` 或 `targetId`，通话记录通过来源字段标记为“浏览器测试”。

`businessId` 不得代替 `taskId` 或 `targetId`。

### 5.2 通话来源

通话记录使用 `entryType` 表示电话从哪个入口进入系统：

| `entryType` | 页面名称 | 含义 |
| --- | --- | --- |
| `web` | 浏览器测试 | 来自通话测试台，不关联正式外呼任务 |
| `sip_outbound` | SIP 外呼 | 正式单号码或批量名单外呼 |
| `sip_inbound` | SIP 呼入 | 客户主动呼入，不属于本次外呼任务 |

单号码和批量名单都属于 `sip_outbound`，通过任务类型和 `taskId` 区分，不能增加新的通话来源值来区分二者。

后端返回未知 `entryType` 时，页面保留原始值展示，不能错误映射成已有来源。

### 5.3 外呼对象与通话记录

- 一个任务包含一个或多个外呼对象。
- 一个外呼对象可以因重试产生多次拨打。
- 每次真实拨打生成一条独立通话记录。
- 外呼对象描述整体处理进度，通话记录描述每一次拨打过程。

例如，同一号码首次无人接听、第二次接通：

- 外呼对象仍为一条；
- 通话记录为两条；
- 外呼对象拨打次数为 2，最终结果为“已接通”。

## 6. 创建任务

### 6.1 页面结构

创建任务采用单页表单，按以下区域组织：

1. 基本信息。
2. 外呼对象。
3. AI 配置。
4. 执行计划。
5. 系统规则摘要。
6. 校验结果和确认操作。

页面不展示草稿入口，也不展示“上一步 / 下一步”。

### 6.2 基本信息

| 字段 | 规则 |
| --- | --- |
| 任务名称 | 必填，用于列表识别 |
| 外呼方式 | 必填，单号码或批量名单 |

### 6.3 单号码

| 字段 | 规则 |
| --- | --- |
| 手机号 | 必填，按后端统一规则校验 |
| 客户名称 | 选填 |

V1 不增加公司名称、产品名称或任意业务参数。

### 6.4 批量名单

模板只包含以下业务字段：

| Excel 表头 | 对应字段 | 规则 |
| --- | --- | --- |
| 手机号 | `phoneNumber` | 必填 |
| 客户名称 | `customerName` | 选填 |

系统导入时额外记录原文件数据行号，用于校验错误定位。行号以用户在表格软件中看到的行号为准，包含标题行带来的偏移。

批量名单上传区域提供“下载名单模板”按钮，通过 `POST /ai-call/outbound-targets/import-template` 下载由服务端生成的 `外呼名单导入模板.xlsx`。模板数据页第一行固定为“手机号、客户名称”，不预置示例客户数据，避免用户未删除示例行就发起外呼。下载失败时保留当前表单并显示明确错误。

批量名单由通用外呼校验接口直接接收，前端不接入公共 OSS 或 AI Call OSS：

1. 用户选择名单文件时只保存在浏览器本地，不自动上传。
2. 用户点击“校验任务”后，前端向 `POST /ai-call/outbound-validations/batch` 提交 `multipart/form-data`。
3. multipart 只包含 `file` 和 `request` 两部分；`file` 是原始 Excel 文件，`request` 是待校验外呼参数的 JSON 字符串。
4. 接口受理并持久化校验批次后返回 `validationId` 和 `VALIDATING`，前端根据 `validationId` 轮询最终结果。

同一个“校验任务”操作覆盖上传与受理，不增加独立上传步骤。请求发出到取得 `validationId` 前显示“正在上传名单”；取得 `validationId` 后显示“名单校验中”。

V1 的文件边界：

- 只接受单个 `.xlsx` 文件，文件大小上限为 10 MB，前端和后端都必须校验；
- 后端负责解析 Excel，并把解析结果写入校验批次表和校验明细表；前端不解析名单内容；
- 受理、解析、校验、问题分页、导出和确认均使用当前登录用户及其租户上下文；
- 前端契约不包含文件 URL、对象存储路径或文件存储标识，不依赖公共 OSS、AI Call OSS 或公开桶；
- 原文件是否以及如何保留属于后端内部实现，不得改变 `validationId` 契约或向前端暴露存储细节。

### 6.5 AI 配置

任务只允许选择：

- 已保存的提示词配置；
- 可用音色。

当前提示词配置没有版本控制或发布流程，任务页面不新增这两项能力，也不编辑提示词正文。所选配置不存在、场景编码为空或执行所需内容不完整时，不能通过最终校验。

### 6.6 执行计划

- 立即执行：确认启动后进入执行队列。
- 定时执行：必须选择未来时间，确认后进入“待执行”。

定时任务执行前只允许修改任务名称和计划执行时间。外呼名单、提示词、音色和呼叫规则不可修改；配置错误时取消任务并重新创建。

任务开始执行后所有配置锁定。

### 6.7 呼叫规则

呼叫规则在独立页面统一维护，至少包含：

- 每日允许呼叫时间段；
- 最大重试次数；
- 各次重试间隔；
- 哪些拨打结果允许重试。

任务创建页只选择规则并展示只读摘要，不允许任务内覆盖。

呼叫规则列表支持删除。删除采用业务软删除：

- 删除后不再出现在规则列表和新建任务的规则下拉框中，页面不提供恢复入口；
- 已创建任务继续使用创建时保存的规则快照，不受删除影响；
- 已校验但尚未确认创建的任务，其校验结果立即失效，必须重新选择规则并校验；
- 确认创建任务时发现规则已删除，必须阻止创建并提示用户重新选择；
- 后端保留删除记录和历史关联，不执行物理删除。

删除前二次确认文案固定为：

> 确认删除呼叫规则“{规则名称}”吗？删除后不能用于新任务，已创建任务仍按原规则执行。此操作不可恢复。

## 7. 校验与人工确认

### 7.1 流程

1. 用户填写表单或选择名单文件。
2. 用户点击“校验任务”。
3. 批量名单通过 multipart 直接上传并创建异步校验；单号码直接进行同步校验。
4. 系统校验外呼对象、AI 配置、呼叫规则和执行时间。
5. 校验失败时展示问题明细，不能创建任务。
6. 校验通过时展示确认摘要。
7. 用户点击“确认启动”。
8. 服务端以幂等方式创建任务。
9. 立即任务进入执行队列，定时任务进入“待执行”。

校验通过不代表任务已经创建，异步接口返回“已受理”也不代表校验已经完成。

### 7.2 校验内容

- 必填字段。
- 手机号格式。
- 名单内重复手机号。
- 空行和无法识别的数据。
- 所选提示词配置是否仍然存在，场景编码和执行所需内容是否完整。
- 音色是否仍可用。
- 所选呼叫规则是否仍然存在且处于启用状态。
- 呼叫规则是否至少包含一个有效呼叫时段。
- 每个呼叫时段的开始时间必须早于结束时间，多个时段不得重叠。
- 重试次数必须为非负整数且不超过平台上限。
- 每个重试间隔必须为正数，间隔数量必须与重试次数一致。
- 可重试结果只能来自系统支持的结果枚举。
- 立即执行时，当前时间是否处于允许呼叫时段；否则阻止确认并提示下一个允许呼叫时段。
- 定时执行时，计划时间是否仍在未来且处于允许呼叫时段；否则阻止确认并提示修改时间。

单号码可以同步返回校验结果；批量名单统一使用异步校验，避免根据文件大小切换两套批量交互。

### 7.3 批量名单异步校验

批量名单的接口顺序固定为：

1. 调用批量名单校验接口，以 multipart 提交 `file` 和 JSON 字符串 `request`。
2. 校验服务完成请求级文件检查并创建校验批次，返回 `validationId`、`VALIDATING` 和“已受理”语义。
3. 后端异步解析文件，把解析结果写入校验批次和校验明细，再执行系统校验。
4. 前端根据 `validationId` 轮询最终状态。

批量名单校验接口必须接收 `multipart/form-data`，不能再接收文件存储标识、文件 URL 或对象存储路径。`request` 的 JSON 结构与单号码校验共用的任务配置字段保持一致，但 `taskMode` 固定为 `batch`。接口返回成功只表示校验批次已受理，不表示文件解析或系统校验完成。

轮询状态：

- `VALIDATING`：继续轮询；
- `PASSED`：展示确认摘要；
- `FAILED`：展示问题明细；
- `SYSTEM_ERROR`：展示 `errorMessage`，并根据 `retryAction` 要求重新上传或允许按当前校验批次重试。

轮询建议每 2 秒一次，同一 `validationId` 采用单飞请求：上一轮查询未结束时跳过新的 tick，避免慢接口产生请求堆积或响应饥饿。页面离开或校验结束后停止。超时不应被前端误判为失败，用户可手动刷新校验状态。

每次批量校验都生成前端生命周期代次。用户替换文件或修改任一任务配置时，当前代次立即失效；旧上传、旧轮询或旧重试响应即使随后返回，也不得恢复校验结果或确认摘要。前端提交异步结果前必须同时确认代次和当前 `validationId`，避免新页面状态误用旧名单。

`SYSTEM_ERROR` 必须返回 `retryAction`，前端据此提供唯一正确的恢复操作：

| `retryAction` | 含义 | 前端操作 |
| --- | --- | --- |
| `REUPLOAD` | 文件解析前或解析过程中失败，服务端没有可复用的完整解析数据 | 提示重新选择并上传完整 `.xlsx` |
| `RETRY_VALIDATION` | 解析数据已完整入库，后续系统校验发生可重试错误 | 调用 `POST /ai-call/outbound-validations/{validationId}/retry`，不重复上传 |

重试接口成功返回同一个 `validationId` 和 `VALIDATING`。`validationId` 标识一次名单上传形成的校验批次，`taskId` 仅在校验通过并由用户确认后生成；二者不能混用。

### 7.4 问题数据

只要存在一条业务数据错误，整份名单不能创建任务。

页面展示：

- 问题总数；
- 按错误类型统计；
- 问题数据分页表格；
- 按手机号和错误类型筛选；
- “下载问题明细”操作。

问题表格字段：

| 字段 | 说明 |
| --- | --- |
| 原文件行号 | 明确到用户看到的表格行 |
| 手机号 | 原始手机号内容 |
| 客户名称 | 原始客户名称 |
| 错误原因 | 一个数据行可以有多个原因 |
| 重复位置 | 重复手机号需要标明关联行号 |

页面不允许在线修改、删除或跳过问题行。

用户在线下修正原始完整名单后，重新上传整份名单。新文件创建新的 `validationId`，并整体替换页面上一次待确认的校验结果，系统重新校验全部数据。校验通过前不正式生成外呼对象，因此不会产生重复导入或重复外呼。

解析数据已完整入库后发生 `SYSTEM_ERROR` 且 `retryAction=RETRY_VALIDATION` 时，可以按原 `validationId` 重试系统校验。解析阶段失败或名单存在业务数据错误时必须重新上传修正后的完整原文件。

页面提示文案：

> 请根据问题行号修正原文件，并重新上传完整名单。

### 7.5 确认摘要

确认区至少展示：

- 任务名称；
- 外呼方式；
- 有效外呼对象数量；
- 提示词名称和场景编码；
- 音色；
- 呼叫规则摘要；
- 立即或定时执行时间。

确认摘要不是单独页面或弹窗。校验状态为 `PASSED` 后，在创建页面底部、校验结果下方显示确认卡片，“确认启动”按钮放在该卡片内。

“确认启动”必须防重复点击，并由后端幂等键避免重复创建任务。

## 8. 执行配置快照

任务确认时保存该任务实际使用的执行配置快照，包括：

- 提示词配置标识、场景编码和实际执行内容快照；
- 音色标识和必要运行参数；
- 可呼叫时间；
- 最大重试次数；
- 重试间隔；
- 可重试结果集合。

配置中心后续变更只影响新任务，不改变已创建任务。

“配置快照”是后台机制，不作为用户菜单或表单术语。任务详情只显示“本任务使用的提示词名称、场景编码、音色和呼叫规则”。

当前提示词配置会被原地更新，因此任务不能只保存配置 ID，必须保存当时实际执行的提示词内容。快照 JSON 使用 `text` 等通用字段存储，不绑定 `jsonb`。

## 9. 状态模型

### 9.1 任务状态

| 状态 | 含义 | 可用操作 |
| --- | --- | --- |
| `SCHEDULED` 待执行 | 等待定时执行 | 修改名称/时间、取消、查看 |
| `RUNNING` 执行中 | 可以继续产生新拨号 | 暂停、停止、查看 |
| `PAUSING` 暂停中 | 已停止新拨号，等待活动通话结束 | 查看 |
| `PAUSED` 已暂停 | 当前无活动通话，可恢复 | 恢复、停止、查看 |
| `STOPPING` 停止中 | 已停止新拨号，等待活动通话结束 | 查看 |
| `STOPPED` 已停止 | 剩余对象已取消，不可恢复 | 查看 |
| `COMPLETED` 已完成 | 所有对象均得到最终处理结果 | 查看 |
| `FAILED` 执行异常 | 任务级系统错误导致无法继续 | 查看 |
| `CANCELLED` 已取消 | 待执行任务被取消 | 查看 |

单个号码无人接听或拨打失败不代表任务进入 `FAILED`。只要系统正常处理完全部对象，任务进入 `COMPLETED`。

### 9.2 外呼对象处理状态

对象处理状态和最近一次拨打结果必须分开：

| 处理状态 | 含义 |
| --- | --- |
| `PENDING` 待拨打 | 尚未产生拨打 |
| `DIALING` 拨号中 | 正在发起本次拨打 |
| `IN_CALL` 通话中 | 已接通且尚未结束 |
| `RETRY_WAIT` 等待重试 | 当前结果满足重试规则 |
| `COMPLETED` 已处理 | 已得到最终结果 |
| `CANCELLED` 已取消 | 因任务停止或取消不再拨打 |

最近一次拨打结果可包含：已接通、无人接听、忙线、拒接、号码无效、呼叫失败等。

任务进度按“已得到最终处理结果的对象数 / 外呼对象总数”计算，不能按通话记录数量计算。

### 9.3 平滑暂停

暂停任务时：

1. 立即停止产生新的拨号和重试。
2. 已振铃或已接通的通话继续自然结束。
3. 未拨打和等待重试对象保持原状态。
4. 活动通话全部结束后，任务从 `PAUSING` 进入 `PAUSED`。
5. 恢复后从剩余对象继续，不重复处理已完成对象。

### 9.4 平滑停止

停止任务时：

1. 立即停止产生新的拨号和重试。
2. 已振铃或已接通的通话继续自然结束。
3. 未拨打和等待重试对象进入 `CANCELLED`。
4. 活动通话全部结束后，任务从 `STOPPING` 进入 `STOPPED`。
5. 已停止任务不可恢复。

V1 不提供“强制挂断所有当前通话”。

### 9.5 取消定时任务

待执行任务只能取消，不能暂停。取消后进入 `CANCELLED`，不会生成真实拨打记录。

### 9.6 异步操作

暂停、恢复、停止和取消接口返回成功，只表示操作已受理。前端必须继续查询任务状态，直到进入目标状态或返回明确错误。

操作按钮在请求提交后进入加载状态，并在任务处于 `PAUSING` 或 `STOPPING` 时禁止重复提交。

## 10. 任务列表

### 10.1 查询

支持：

- 任务名称；
- 任务状态；
- 创建时间范围。

列表使用服务端分页，默认每页 20 条。记录总数显示在分页区域。

### 10.2 展示字段

- 任务名称；
- 外呼方式；
- 外呼对象总数；
- 已完成对象数和进度；
- 接通对象数；
- 任务状态；
- 计划执行时间或实际开始时间；
- 创建人；
- 操作。

操作列固定在右侧，危险操作使用明确影响范围的二次确认。

### 10.3 刷新策略

- 首次进入自动查询。
- 提供手动刷新。
- 页面存在 `RUNNING`、`PAUSING` 或 `STOPPING` 任务时，每 10 秒刷新当前页。
- 页面不可见或不存在活动任务时停止自动刷新。

## 11. 任务详情

任务详情不使用“执行概览、通话记录、任务事件”多 Tab 结构。

### 11.1 顶部

展示：

- 任务名称和状态；
- 外呼对象总数；
- 已完成数；
- 接通数；
- 失败数；
- 执行进度；
- 创建、计划、开始和结束时间；
- 提示词名称和场景编码；
- 音色；
- 呼叫规则摘要。

### 11.2 外呼对象列表

支持手机号、客户名称和处理状态筛选，使用服务端分页。

字段：

- 客户名称；
- 手机号；
- 处理状态；
- 拨打次数；
- 最近拨打结果；
- 最近更新时间；

操作包括“查看通话记录”。任务级按钮带 `taskId` 跳转，外呼对象按钮同时带 `taskId` 和 `targetId` 跳转。

### 11.3 详情刷新

任务处于活动状态时，每 5 秒刷新任务摘要和当前对象列表；暂停、停止、完成、失败或页面不可见后停止轮询。

## 12. 统一通话记录集成

仓库现有《AI Call 通话记录 V1 设计》先服务浏览器测试和已有 SIP 数据，不依赖尚未实现的外呼任务。本设计不会修改或覆盖该规格。

通用外呼任务后端落地后，通话记录需要增量支持：

- `taskId`；
- `targetId`；
- 客户名称；
- 任务筛选；
- 外呼对象筛选；
- 来源筛选；
- 拨打轮次；
- AI 通话结论；
- 一到两行通话摘要。

查询条件增量支持：

- 任务名称或任务 ID；
- 手机号；
- 客户名称；
- 通话来源；
- 呼叫结果；
- 通话时间范围。

从外呼对象跳转时，页面通过 URL 中的 `targetId` 精确筛选；`targetId` 不要求运营人员手工输入。

### 12.1 列表推荐展示

为避免字段太少但又不把详情全部塞入表格，列表采用复合列：

| 复合列 | 内容 |
| --- | --- |
| 通话时间 | 开始时间 |
| 客户信息 | 客户名称、手机号 |
| 任务信息 | 任务名称、通话来源 |
| 呼叫情况 | 呼叫结果、拨打轮次、通话时长，失败时显示失败原因 |
| AI 分析 | AI 结论标签、一到两行摘要 |
| 录音 | 有录音时提供快捷播放 |
| 操作 | 查看详情 |

摘要超出后省略，悬浮可查看完整摘要。没有结构化 AI 结论时显示“—”，不能由前端猜测。

### 12.2 仍放在详情中的内容

- 完整录音播放器；
- 完整对话转写；
- 完整 AI 结构化结果；
- 提示词配置快照和音色信息；
- 转人工记录；
- 通话技术参数；
- 原始错误；
- 技术事件和状态时间线。

详情中的录音、对话、AI 分析、转人工和技术事件继续独立加载，一个区域失败不能阻断其他区域。

## 13. 异常处理

### 13.1 创建与校验

- 文件类型或大小不符合要求：前端不发送请求，提示只接受单个不超过 10 MB 的 `.xlsx`。
- 上传请求失败或响应缺少 `validationId`：保留当前表单和本地文件，允许重新发起直接上传。
- 解析阶段异常：返回 `SYSTEM_ERROR`、`retryAction=REUPLOAD` 和明确 `errorMessage`，要求重新上传完整名单。
- 解析数据已入库后的系统校验异常：返回 `SYSTEM_ERROR`、`retryAction=RETRY_VALIDATION` 和明确 `errorMessage`，允许按原 `validationId` 重试。
- 校验结果已过期：要求重新校验，不能直接确认启动。
- 确认时配置失效：阻止创建，指出具体失效配置。
- 重复确认：通过按钮防重和后端幂等键避免重复任务。

### 13.2 执行

- 任务级错误统一保存明确的 `errorMessage`。
- 单次拨打失败保存到对应通话记录，并按呼叫规则判断是否重试。
- 重试按到期对象分页获取，不能一次把全量名单加载到内存。
- 页面上的失败原因使用业务化文案，技术原始错误放在详情。
- 服务端状态为准，前端不能仅因网络超时把操作标记为失败。

### 13.3 配置和资源变化

- 配置中心修改不影响已创建任务的执行快照。
- 外部音色、线路等资源在执行前仍需做可用性检查。
- 外部资源不可用时，必须记录明确失败原因，不能静默跳过对象。

### 13.4 接口响应

通用外呼接口与现有若依及催收接口保持一致，普通 JSON 接口只返回以下两种外壳：

```ts
type ApiResponse<T> = {
  code: number;
  msg?: string;
  data?: T;
};

type TableDataInfo<T> = {
  code: number;
  msg?: string;
  rows: T[];
  total: number;
};
```

- 普通详情、创建和状态操作使用 `ApiResponse<T>`。
- 分页查询使用 `TableDataInfo<T>`，不能把分页结果嵌套进 `data`。
- `code === 200` 表示请求成功；其他状态码统一按若依错误处理流程处理。
- 后端不能返回没有 `code` 的裸对象或裸数组，前端也不为裸响应增加兼容分支。
- 文件下载成功时直接返回 Blob；下载失败时返回包含 `code` 和 `msg` 的 JSON 错误外壳。

## 14. 权限与审计

至少区分：

- 查看任务；
- 创建任务；
- 修改待执行任务；
- 暂停/恢复任务；
- 停止/取消任务；
- 查看通话详情和录音；
- 删除呼叫规则；
- 下载名单模板；
- 下载问题名单。

任务创建、修改执行时间、暂停、恢复、停止、取消和规则删除必须记录操作人、操作时间、操作对象、操作前状态和操作后状态。V1 不需要单独“任务事件”Tab，但审计数据必须保留，供后续排障或审计页面使用。

## 15. 数据实现约束

- 需要租户隔离的任务、外呼对象、校验任务和通话记录必须使用项目统一租户能力。
- 批量上传受理时必须把当前 `tenant_id` 固化到校验批次，后续轮询、重试、问题分页、导出和确认均校验租户归属。
- 后端解析结果进入校验批次和校验明细表，不能依赖浏览器长期持有文件，也不能把全量问题数据返回前端。
- 业务关联通过索引、唯一约束和代码校验保证，不创建物理外键。
- 配置快照和扩展结果使用通用 `text` 存储 JSON 字符串。
- 批量名单、问题明细和待执行对象均使用服务端分页。
- `validationId`、`taskId`、`targetId`、`callId` 等 ID 返回前端时使用字符串。
- 任务确认、状态操作和通话回调需要幂等。

## 16. 前端验收标准

1. 用户可以在一个页面完成单号码或批量名单任务配置。
2. 单号码只要求手机号，客户名称选填。
3. 批量名单上传区域可以下载只包含“手机号、客户名称”表头的 Excel 模板。
4. 批量名单由一个“校验任务”操作直接 multipart 上传并创建异步校验，页面能分别展示“正在上传名单”“名单校验中”和最终结果。
5. 删除呼叫规则后，该规则从列表和新任务选项中消失，已创建任务仍显示并使用原规则快照。
6. 任一错误行都会阻止创建，页面能定位原文件行号、手机号和错误原因。
7. 问题明细可以下载，修正后的完整名单可以替换重传。
8. 校验通过后，创建页面底部显示确认卡片，必须由用户确认后才正式创建任务。
9. 重复点击确认不会创建两个任务。
10. 定时任务执行前只允许修改名称和执行时间。
11. 任务可以按本设计平滑暂停、恢复和停止。
12. 任务列表和详情能够准确展示任务进度，且进度不按通话记录数计算。
13. 任务详情只保留外呼对象列表，不复制通话记录。
14. 任务和外呼对象可以跳转统一通话记录并自动带入筛选条件。
15. 通话记录能区分浏览器测试和正式外呼。
16. 同一外呼对象多次重试产生多条通话记录。
17. 通话记录列表能够直接看到 AI 结论、摘要和录音入口。
18. 任一详情附属接口失败不会导致完整通话详情不可用。
19. 页面查询、异步轮询、按钮状态、危险操作确认和空状态均有自动化测试。

## 17. 后端验收标准

1. 校验通过前不正式生成任务外呼对象。
2. 校验结果、任务创建和任务操作均支持幂等。
3. 任务、外呼对象、通话记录和业务标识关系符合第 5 节定义。
4. 配置中心变更不影响已创建任务的执行快照。
5. 暂停和停止不会强制挂断已接通通话。
6. 等待重试对象在暂停时保留，在停止时取消。
7. 单次拨打失败不会错误地把整个任务标记为执行异常。
8. 批量名单校验、任务调度和重试均按批次分页处理。
9. 异步接口只返回受理状态，最终状态可以通过查询接口获取。
10. 任务级和拨打级失败均保存可展示的明确错误原因。
11. 批量校验接口只接收 multipart 的 `file` 和 JSON 字符串 `request`，返回字符串 `validationId` 和 `VALIDATING`。
12. 名单模板下载接口返回可被当前名单解析规则识别的 Excel 文件。
13. 呼叫规则删除采用软删除，不能影响已创建任务的规则快照和执行。
14. 批量校验只接受单个不超过 10 MB 的 `.xlsx` 文件，并把解析结果写入当前租户的校验批次和明细。
15. 解析失败要求重新上传；解析数据已入库后的可重试系统校验错误支持按同一 `validationId` 重试。
16. 任一租户不能查询、重试、导出或确认其他租户的 `validationId`。

## 18. 与后续业务适配的边界

未来物业催收、营销、通知、回访等业务通过 `businessId`、业务类型和结构化 AI 结果接入，但不能改变通用任务、外呼对象、拨打记录和状态机的核心关系。

业务适配可以增加业务字段、结果映射和专属看板，但不应把催收金额、账龄、案件状态等字段直接加入通用外呼任务表或 V1 通用页面。
